Not sporadic single injections - two rapid toggle storms

Despite the name, "sporadic sensor measurement injection" is not many scattered single writes - it is dense write-toggle bursts (~100 Write Single Coil requests each, ~ requests/sec), rapidly flipping the SAME coil (address ) between ON and OFF in a near-random pattern.

Burst 2 is not a new event - it's a continuation of naive-sensor-read's write coda

Verified directly from the raw data, not assumed: this is the same physical write-toggle sequence on the same TCP connection, just split across two different attack-type labels.

TCP stream 6823 carries ONE continuous, unbroken write-toggle sequence from t = 5356.43s to t = 5366.51s (, requests total, same ~51ms cadence throughout, no gap or content change at the boundary) - but the dataset's attack_specific label switches from 4 to 5 partway through, at t = 5357.196s. The first requests were already shown in the naive-sensor-read report as a "short write coda" under attack_specific=4 - that description was accurate but incomplete: the remaining requests of that SAME event are labeled attack_specific=5 instead, and appear here as "burst 2". This is a different kind of labeling issue from the background-noise co-mingling documented below: there, unrelated legitimate traffic gets swept into an attack's active window; here, a single malicious event is itself split across two different attack-type ground-truth labels. Any accuracy metric computed strictly per attack_specific label should account for this.
