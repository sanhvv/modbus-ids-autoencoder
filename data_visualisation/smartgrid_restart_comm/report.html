The same diagnostic call, ten times, every three seconds, ten times over

"Restart communication" is pure Modbus Diagnostics (fc8) - rounds, each opening a brand-new TCP connection, each firing identical fc8 requests at an almost perfectly regular interval, spread across of the session. Unlike force listen mode, the response here is the STANDARD fc8 shape - the tell is the repeated, clockwork-regular cadence, not the reply.

A note on the "Restart Communications Option" framing

Same caution applied to force listen mode - being precise about what this dataset's columns do and don't let us verify.

Modbus's real "Restart Communications Option" is Diagnostics sub-function 0x01 - consistent with this attack's assigned name. This capture's modbus_data field shows an empty/zero value for every request, which does not let us independently confirm the sub-function byte from this column alone. What IS independently verifiable: this attack's response is bytes - the SAME standard shape fc8 gets under function-code scan and address scan ( bytes), unlike force listen mode's shortened 10-byte response. So whatever protocol effect force listen mode triggers on the target, this attack does not trigger the same one - the concrete signal here is the request PATTERN (10 identical requests, ~3.0s apart, repeated over 10 separate rounds), not the reply shape.
